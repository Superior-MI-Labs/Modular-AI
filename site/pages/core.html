CORE CONTRACT / FILE-LEVEL BUILD PLAN

Define complete before calling it complete.

The core will be frozen when it proves it can load, validate, orchestrate, record and compare modular experiments without knowing the model family. New models should then arrive as modules and workflow controllers, not modifications to the kernel.

THE FROZEN BOUNDARY

Small responsibilities. Strong contracts.

Full file plan ↗
01 / STABLE

Core kernel

02 / EXTENSIBLE

Workflow controllers

03 / REPLACEABLE

Modules and adapters

CORE FREEZE CRITERIA

Eight gates, with real evidence.

01

Contract gate

Schema IDs, representation dependencies, versions, capabilities and negative tests.

02

Swap gate

Two real decision policies; configuration-only selection; invalid combinations rejected.

03

Workflow gate

Episode, token and iterative controllers with no kernel modifications.

04

Training gate

Train, checkpoint, resume and reproduce a small CPU reference model.

05

Artifact gate

Immutable models, checkpoints, derivatives, datasets and their provenance.

06

Reliability gate

Failure, cancellation, budgets and recovery covered by tests.

07

Extension gate

A separately registered module and workflow works without editing core files.

08

Documentation gate

Stable public API, versioning, migration examples and diagnostic guides.

IMPLEMENTATION MAP

Every file has a reason.

Planned Python files are recorded by path, responsibility and acceptance gate. Empty placeholders do not count as implementation. The compatibility checker is the first actual core prototype.
